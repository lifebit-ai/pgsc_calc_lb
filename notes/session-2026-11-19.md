## Implementation Decision

- Use a dedicated `cancer_shard_probe.nf` entry point on `john_test_05`.
- Declare the VCF and index together as one Nextflow `path` tuple.
- Use the already accepted `ghcr.io/pgscatalog/pyyaml:6.0` image.
- Do not create or publish another VCF copy.
- Stream the complete gzip input, count variant records, and hash only
  `CHROM`, `POS`, `REF`, and `ALT` fields.
- Publish a TSV receipt containing task-local file and filesystem metadata,
  index checksum, variant count/digest, and allowlisted Azure Batch IDs when
  available.
- Never publish VCF headers, sample IDs, genotypes, variant rows, source URIs,
  credentials, or a full environment dump.
- Disable Nextflow report, trace, timeline, and DAG publication for this
  diagnostic branch because an execution report can repeat the full launch
  command, including a signed file-selector URL. Retain the managed Lifebit log
  privately instead.
- Stage the selected inputs under fixed safe task names and validate the shard
  label before task creation so runtime paths and labels cannot alter the shell
  command.
- Replace the full-pipeline schema on this diagnostic branch with a minimal
  schema for `input_vcf`, `input_index`, `shard_label`, and `outdir`. Restore the
  full schema when `main.nf` becomes the entry point again.
- Use on-demand main and worker instances for the diagnostic run so worker
  interruption is not a confounding failure mode.
